# Pipeline 1 — Verifier Benchmark

Benchmarks the **stage-3 verifier** (different BERT families **vs.** the spaCy
baseline **vs.** a no-verifier reference) on the mandated chain, holding stages
1/2/4/5 fixed:

```
txt → (1) GLiNER → (2) GLiREL → (3) BERT/spaCy verifier → (4) SHACL → (5) KG assembly
```

Two evaluation levels:

| level | what it measures | data |
|---|---|---|
| **intrinsic** | VALID/INVALID classification: accuracy, macro-F1, and **rejection recall per hard-negative type** (`hard` / `direction` / `dr`) | `generated/verifier_test.jsonl` |
| **end-to-end** | the full chain → triples; per tier: `entity_recall` (s1), `candidate_recall` ceiling (s2), triple **P/R/F1** (s3), and **KG-level P/R/F1** (s5) | `qud_tiered_annotated.jsonl` **test** split |

> **Data source = the tiered 100-text set** (`qud_tiered_annotated.jsonl`), split
> **70 / 15 / 15** into train/val/test. The verifier is trained, validated and tested on
> it end-to-end. (The 300-story corpus path still exists — see *Legacy* below — but is no
> longer the default.) ⚠️ 70 training texts is a small set: expect data-starved, less
> stable verifier training.

## Data prep: tiered 300 → 70 / 15 / 15

The tiered set is now **300 texts (75 per tier)**: the original hand-authored qt_001–100
plus 200 generated by `gen_tiered_expand.py` (qt_101–300, hard-validated against the ABox
gold). Split + (re)build the verifier dataset. Re-run whenever the tiered texts or the
split change — this **invalidates previously trained models → retrain**:

```powershell
python gen_tiered_expand.py                # only if regenerating qt_101-300 (aborts if present)
python split_tiered.py                     # 300 texts -> 210/45/45, writes `split` into qud_tiered_annotated.jsonl (stratified by tier)
python build_verifier_from_tiered.py       # -> verifier_{train,val,test,all}.jsonl (VALID/INVALID + hard/direction/dr, leakage-purged test>val>train)
```

Produces ~1507 rows (train 1042 / val 217 / test 248). **Object-triple coverage is complete
(0 marking misses)** and **every object triple's subject+object co-occur in ONE sentence in
all four tiers** (584/584 verified) — required for GLiNER+GLiREL to form candidates, since
the pipeline is per-sentence. 8 datatype triples remain unmarked — `Tier` low/mid/high and
`Boss` true/false (redundant with `hasRole`), `strata` written "three", and the two
zero-values ("weightless"/"worth nothing") — counted in `verifier_stats.json`.

**Tier semantics:** entities always canonical (synonyms ONLY on relations);
`long_distance` = ONE long sentence with ≥15 filler tokens between subject and object
(cross-sentence distance is impossible for a per-sentence pipeline — candCeil would be 0).

**Pipeline fixes that raise candidate recall** (`infer_pipeline.py`):
- `sent_split` masks ontology labels containing `.!?` ("Weirdwire Conduit... Eureka!",
  "Pax Qlanq, I Presume?") so the splitter no longer breaks inside quest names;
- `_ground` falls back to stripping a leading "the " **only after** the exact alias match
  fails — "the Barathrumites" now grounds, while "The Golem"/"The Earl of Omonporch"
  (article part of the name) still ground exactly;
- **stage 1 = GLiNER ∪ alias-dictionary**: GLiNER returns partial spans of long names
  ("Weirdwire Conduit" + "Eureka!", "Urshiib race", "Carbine") that fail grounding, so its
  grounded spans are unioned with the exact alias matcher — known individuals are always
  found, GLiNER keeps contributing typing/open spans. The alias dictionary now also carries
  the role surfaces ("boss-tier fighter", "mid-tier merchant", ... via `ROLE_SURFACE_ALIASES`
  in `build_qud_dataset.py`), so `hasRole` triples are groundable end-to-end;
- **stage 2 = GLiREL ∪ domain/range pairwise** (`--stage2-union`, default ON;
  `--no-stage2-union` = pure GLiREL; `--glirel-topk`, default 3): GLiREL's zero-shot recall
  over 28 fine-grained labels was the ceiling (0.5–2.7 candidates/unit) — the union hands
  every type-compatible pair to the verifier, whose filtering is the architecture's thesis.

## Run it

**1) Train the verifier zoo** (5 transformers + spaCy baseline; `--force` retrains stale ones after a re-split):

```powershell
python bench_train_all.py --force        # defaults: lr 1e-5, 20 epochs, batch 8, warmup 0.1 (T5 lr auto 1e-4)
# subset:  python bench_train_all.py --only xlnet-base-cased,t5-base
```

> ⚠️ **Fine-tuning stability (important).** On this small set (~1.6k rows) RoBERTa /
> XLNet / BigBird show classic small-data instability: at **lr 2e-5** they thrash
> (val macro-F1 bounces ~0.55–0.65) and at **lr ≥ 3e-5 / batch ≥ 16** they collapse
> to the majority class (val macro-F1 ≈ 0.37 every epoch). The stable regime is
> **lr 1e-5, batch 8, warmup 0.1, 20 epochs** — at which they escape around epoch 5
> and converge to ~0.99 by epoch 10. DistilBert is robust to all of these; T5 needs
> lr ≈ 1e-4 (set automatically). Rule of thumb: if a model is stuck at 0.37, **lower
> the LR**, don't raise it; if it thrashes, also lower it and add warmup.

Current zoo (`bench_lib.BERT_ZOO`): `google/bigbird-roberta-base`,
`distilbert-base-uncased`, `xlnet-base-cased`, `roberta-base`, `t5-base`
(all map to a `…ForSequenceClassification` head in transformers ≥5; T5 is used as
an encoder-decoder classifier, not text-to-text). **Add a model** by appending
`(name, hf_id)` to `BERT_ZOO` — naming/locating is automatic.

**2) Run the benchmark** (default: `--models zoo` = the 5 transformers + spaCy + a passthrough reference; default corpus = **`tiered_test`**, the held-out 15% of the tiered set):

```powershell
# fallback stages 1&2 (alias-dict NER + domain/range pairwise) — fast, no GLiNER/GLiREL:
python bench_run.py

# REAL stages 1&2 (the actual benchmark), on the tiered test split:
python bench_run.py --use-gliner --use-glirel

# other corpora: tiered_train | tiered_val | tiered_test | tiered (all 100) | story_* (legacy). + SHACL at stage 4:
python bench_run.py --use-gliner --use-glirel --corpus tiered --shapes ..\generated\shapes.ttl
```

## Reading the numbers

- **`entRec` / `candCeil`** are stage-1 / stage-2 metrics — **identical across verifiers**
  (same GLiNER/GLiREL). `candCeil` is the **maximum recall any verifier can reach**;
  if final R ≈ candCeil the verifier keeps everything reachable, the loss is upstream.
- **`passthrough`** = stage-3 OFF (accept all candidates). Its precision is the floor;
  the gap to a trained verifier is the value the verifier adds. With `--stage2-union`
  (default) passthrough accepts EVERY type-compatible pair, so its precision is
  deliberately low — that headroom is exactly what the verifiers are measured on.
- **Verifier training plateaus:** DistilBERT/XLNet/spaCy converge by ~epoch 20; RoBERTa,
  BigBird and T5 sit on a flat mid-plateau at 20 epochs and need the **40-epoch** recipe
  (`bench_train_all.py --only roberta-base,bigbird-roberta-base,t5-base --epochs 40 --force`).
- A good verifier **raises precision while holding recall near `candCeil`** and shows
  high `rej:direction` / `rej:hard` (rejects swapped-argument and plausible-but-wrong triples).

## Notes / scope

- **Tiered set — synonym resolution is now relation-only.** In the `implicit`,
  `long_distance` and `nested` tiers the **subjects and objects use their canonical
  names**; only the **relation** is paraphrased (*"can't abide"* = `hates`,
  *"calls home"* = `isHabitantOf`). Entities are therefore groundable by span NER, so
  `entRec` is no longer intentionally depressed on `implicit` — these tiers now isolate
  **relation** phrasing (implicit), **argument distance** (long_distance) and **triple
  density** (nested), not entity coreference. (Datatype/role surfaces like *"boss-tier
  fighter"* stay as-is.)
- **Datatype triples** (HP/level/Tier/…) are evaluated **intrinsically only**: stages 1-2
  emit object-property candidates, so the end-to-end triple metric is object-property scoped.
- The **tiered dataset works directly as the e2e gold** (text + object triples). For training
  GLiNER/GLiREL you'd additionally need character spans — easy for explicit/long/nested
  (label string-match), not for implicit (synonyms).
